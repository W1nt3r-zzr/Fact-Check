# 事实核查AI网页插件

## 项目概述

本项目是一个面向中国普通网民的事实核查AI网页插件，旨在通过结构化的解释内容和直观的呈现形式，提升用户对AI核查结果的信任与采纳。

### 研究问题
面向中国普通网民的事实核查AI产品，应如何设计其解释内容与呈现形式，才能有效提升用户对核查结果的信任与采纳？

### 目标用户
- 中国普通网民
- 非专业事实核查使用者
- 需要快速验证网络信息真实性的用户

### 产品形态
- 网页浏览器插件（Chrome Extension）
- 轻量级、即时、嵌入式体验

## 核心功能

### 用户调研工具（scenario-research/）

这是一个独立的Web应用，用于用户调研和测试，帮助研究者了解用户在不同场景下对AI事实核查介入方式的偏好。

**功能特点：**

1. **5个高保真使用场景**
   - 家庭微信群：长辈转发文章
   - 社交媒体：小红书/头条推荐内容
   - 知识问答：知乎/论坛讨论帖
   - 搜索资料：百度/谷歌搜索结果
   - AI助手对话：Kimi/豆包等AI咨询（含AI幻觉）

2. **3种风险类型**
   - 低风险：养生谣言（生活误区）
   - 高风险：财产诈骗（财产损失）
   - 中风险：社会新闻（情绪煽动）

3. **3种介入方式**
   - 强力弹窗阻断：屏幕中央弹出警告框
   - 侧边悬浮提示：右下角通知条
   - 被动右键调用：右键菜单调用

4. **"分享后链路"行为追踪**（核心创新）
   - 基于用户访谈洞察（李莉芳老师访谈）
   - **家庭微信群场景**：提供"保全面子"的选项
     - 私下发消息给长辈（温和提醒，避免丢脸）
     - 转发给其他家人商量（小群商议）
     - 在群里温和提醒（委婉表达）
     - 不作回应（避免冲突）
     - 在群里直接辟谣（可能伤感情）
   - 其他场景：提供符合平台特性的行为选项
   - 追踪用户看到AI介入后的真实行为选择

5. **7步用户调研流程**
   1. 选择场景
   2. 选择风险类型
   3. 选择AI介入方式
   4. 选择介入位置（预览页/详情页）
   5. 体验模拟界面（查看AI介入效果）
   6. **行为选择**："你会怎么做？"
   7. 体验反馈评分

6. **用户体验反馈**
   - 烦躁程度评分（1-7分，7点李克特量表）
   - 有用程度评分（1-7分，7点李克特量表）
   - 隐私担忧评分（1-7分，7点李克特量表）
   - 行为选择记录
   - 完整数据记录和导出功能

**技术栈：**
- React 18
- Vite（构建工具）
- Tailwind CSS（样式）
- Lucide React（图标库）

**设计亮点：**
- 桌面浏览器模拟界面（900px宽度，统一所有步骤）
- **预览页/详情页高保真区分**：为所有5个场景提供预览和详情两种界面
  - 微信群聊：预览=群聊消息列表，详情=文章内容页
  - 社交媒体：预览=瀑布流推荐，详情=笔记详情
  - 知乎问答：预览=问题列表，详情=问题+回答
  - 搜索引擎：预览=搜索结果列表，详情=网页内容
  - AI助手：预览=对话历史列表，详情=完整对话
- 根据场景提供高保真界面（微信、小红书、知乎、百度、Kimi）
- AI幻觉内容高亮显示（黄色标注）
- **情境化行为选项**：为每个场景定制符合真实使用习惯的行为选择
- **"给台阶下"设计**：家庭微信群场景特别提供保全面子的选项，避免长辈丢脸
- 响应式交互设计
- 数据持久化准备

### Chrome插件（开发中）

基于Warren et al. (CHI '25)的"Show the Work"原则，提供：
- **Why**: 引用具体证据原文
- **How**: 展示检索策略和信源类型
- **Uncertainty**: 标注信息缺口和不确定性

**其他核心功能：**
- 权威信源检索：优先调用.gov.cn、.people.com.cn等高可信域名
- 可验证操作：一键复制证据链接、高亮引用原文
- 轻量交互设计：选中文本即可触发核查

## 技术架构

### 前端（Chrome插件）
- **技术栈**: React + TypeScript
- **规范**: Manifest V3
- **主要功能**:
  - 文本选择和UI交互
  - 与后端API通信
  - 结果展示和用户操作

### 后端服务
- **技术栈**: Python 3.10+ + FastAPI
- **主要模块**:
  - Claim接收与预处理
  - 权威信源检索
  - 结构化推理生成
  - API接口服务

### 外部服务
- **搜索引擎**: Bing Search API
- **大语言模型**: DeepSeek / Qwen / Moonshot API
- **缓存**: Redis（可选）
- **部署**: Docker + Serverless平台

## 关键挑战

### 技术挑战
1. **LLM幻觉问题**: 通过RAG和引用锚定技术降低幻觉风险
2. **信源获取**: 构建高可信源白名单，定期维护
3. **性能优化**: 缓存常见查询，限制并发

### 用户体验挑战
1. **信任建立**: 强调"协查"定位，明确标注AI局限性
2. **理解门槛**: 使用简洁语言，避免专业术语
3. **操作成本**: 提供一键操作，降低验证门槛
